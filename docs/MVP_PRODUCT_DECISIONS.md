# MVP 产品解读与实施决策

本文记录对仓库上一级三份输入文档的解读结果，避免把文档中的目标描述、开发指令和当前迭代范围混在一起。

## 1. 1.0：为什么做

### 已明确的事实

- 产品面向保险机构总部产品经理与一线业务人员。
- 核心问题不是“做一个聊天机器人”，而是把难以表达、难以复制的个人判断过程转成组织经验资产。
- 采集方式是“案例挑战 + AI 深度复盘”：先给同一业务情境，再围绕回答中的信息缺口追问。
- 单人访谈需要覆盖机会发现、判断逻辑、动作选择、效果反馈、边界条件五类信息。
- 最终资产包括个人萃取案例、经验规则和供 Skill 使用的 Markdown Reference。

### 当前无法被证明的内容

- 文档没有现状效率、质量或业务收益基线，因此本 MVP 只能验证流程可行性，不能证明 ROI。
- 没有真实访谈和专家复核时，演示内容只能标记为合成数据或候选假设，不能称为“已验证机构经验”。

## 2. 2.0：做什么

### MVP 产品闭环

1. 管理员创建并发布萃取任务。
2. 业务员通过参与入口了解任务并填写动态资料。
3. 系统生成并冻结一份模拟挑战案例快照。
4. 业务员用文字或语音转写参与访谈。
5. 访谈 Agent 根据五维信息状态继续追问。
6. 提交后生成个人萃取案例与经验规则。
7. 管理员查看原始对话和结果，选择多份访谈进行融合。
8. 生成、审核并导出 Markdown Reference。

### 页面范围

- PC：工作台、任务列表、任务创建、任务详情、访谈详情、经验融合、Reference 预览。
- H5：邀请码入口、任务说明、资料填写、案例挑战、AI 陪练、提交完成。

## 3. 3.0：怎么做

### 采用的约束

- Next.js + TypeScript + Tailwind CSS。
- App Router 的 Route Handlers 作为文档所称的 Next.js API Routes。
- PostgreSQL / Supabase migration 与 seed 纳入仓库。
- 案例生成、访谈萃取、多人融合三个 Agent 独立建模。
- 业务代码只依赖 LLM Gateway 和 Speech Adapter，不绑定模型或 ASR 厂商。
- Prompt 独立存放在 `prompts/`。
- 首轮使用确定性 Mock Provider，后续替换 Provider 时不改变页面和 API contract。

## 4. 冲突处理

| 问题 | 文档差异 | 当前决策 |
| --- | --- | --- |
| 任务发现 | 1.0/2.0 写所有人看全部任务；3.0 写邀请码/二维码 | 采用 3.0 的邀请制，降低机构任务泄露风险 |
| 登录 | 2.0 Sprint 提到登录，但无角色、认证和权限规格 | 本版只做管理员演示壳，不声称具备生产认证 |
| 真实 AI/ASR | 3.0 验收包含 AI/语音；本轮用户明确后续再接 API | 当前只实现可替换接口、Mock 状态机和模拟转写 |
| Case 语义 | 文档用同一词指挑战输入和访谈产出 | 数据库拆为 `challenge_cases` 与 `extracted_cases` |
| Scenario / Task | 页面、API 和数据模型命名混用 | `scenario` 是可复用配置，`task` 是一次带邀请码的发布实例；UI 统一称“萃取任务” |
| 共性经验 | 1.0 目标是共性策略，2.0 又把聚类放到 V2 | 本版提供可追溯的确定性 Mock 融合草稿，不宣称已有真实聚类算法 |

## 5. 当前能力边界

### 本版完成

- 全页面，以及预置任务 `XC2026` 的 H5/Mock API 资料、访谈和提交链路。
- 管理端任务创建为 `localStorage` 交互原型，未与 Mock API/H5 新邀请码打通。
- 管理端访谈、融合和 Reference 视图使用预置演示数据，尚未自动反映 H5 新提交数据。
- PostgreSQL/Supabase schema、RLS 基线、seed 数据，以及可由环境变量切换的 server-side Supabase Repository。默认仍为 Mock 模式。
- Agent / LLM / Speech / Reference 模块接口。
- 合成案例、确定性动态追问、模拟转写和确定性融合。
- Markdown Reference 预览与下载。

### 上线前必须补齐

- 把管理端创建/发布与 Repository、任务邀请入口及 H5 动态数据打通。
- 将管理端访谈列表、融合和 Reference 页切换为 API/Repository 真实状态，形成单一数据闭环。
- 在真实 Supabase 项目执行 migration/seed，并验证 Supabase Repository 的 CRUD、幂等与故障处理。
- Supabase Auth 登录、账号开通/停用、机构成员与任务参与者分配，并在真实隔离环境中验证 RLS。数据库安全基线已存在，但当前没有完整认证体系，因此不可承载真实机构数据；详见 [`DATA_SECURITY_BASELINE.md`](DATA_SECURITY_BASELINE.md)。
- 录音授权、隐私告知、PII 脱敏、文件私有存储、留存与删除策略。
- 真实 LLM/ASR Provider、超时重试、成本控制、可观测性和内容安全。
- 专家审核、规则版本、证据评级与评测集。
- 真实用户访谈验证，不把演示阈值或候选规则直接用于经营决策。
