# 内部试用：访问与数据留存政策（待机构确认）

> 状态：`approved_for_internal_pilot`（2026-08-23）。本文件是当前技术实现的内部试用运行基线；自动删除 worker 上线前，留存期限仍不会自动执行。本文件不替代机构法务、信息安全或档案制度审批。

## 一、访问方案

### 参与者：受控免登录

参与者不需要邮箱、企业微信或注册页面：

```text
管理员生成短时参与链接 / 二维码
→ 浏览器静默创建 Supabase 匿名会话
→ 链接首次领取并绑定该匿名身份
→ 直接填写资料、录音或文字访谈
```

- 原始 token 不落库，只保存 SHA-256 摘要。
- 链接默认单设备领取、可过期、可撤销；转发给另一匿名身份会被拒绝。
- RLS 只允许该参与者读取自己被分配的 task、profile、interview、message、转写和个人结果。
- 这是“无感参与”，不是匿名公开问卷；公开邀请码不能替代受控参与链接。

### 管理员：预置账号密码（最简可用方案）

不接企业微信、SSO 或邮件发送链路，但管理员仍必须有最小认证。推荐使用 Supabase Auth 的预置账号密码：

1. 仅由系统管理员预先创建 1–3 个管理员账号；不开放自助注册、找回密码或成员邀请页面。
2. 每个账号在 `organization_members` 中绑定唯一机构并标记为 `admin`。
3. 管理端登录后使用该用户 JWT 调用 API；服务端继续核验机构成员关系和管理员角色。
4. 不在浏览器使用 service role key，不使用共享“超级口令”，不以受控参与链接访问管理端。

这保留了目前的 RLS 与审计语义，且对管理员只有一次账号密码输入；参与者完全无感。

## 二、已确认的内部试用留存基线

| 数据类别 | 建议默认留存 | 到期动作 | 例外 |
| --- | --- | --- | --- |
| 原始录音、未确认转写 | 30 天 | 删除私有 Storage 对象；清空转写文本；任务标为 `expired` | 有效 legal hold 暂停处理 |
| 已确认访谈文本、参与资料 | 365 天 | 删除或匿名化姓名、机构及自定义可识别字段；保留匿名汇总须经审批 | 法律、投诉或审计留档要求 |
| 个人经验案例、规则草稿、Reference | 依据机构档案制度；试用期建议 3 年上限 | 到期人工复核后删除或匿名化归档 | 已审核且纳入正式知识库的版本按档案制度处理 |
| 访问链接 | 30 天或任务关闭时立即失效 | 标记过期；不保存原始 token | 无 |
| 审计事件、删除记录 | 1 年 | 安全归档或删除 | 事件调查期间保留 |
| 备份中的已删数据 | 最长 30 天 | 按备份轮换自然清除 | 灾难恢复所需最短期限 |

## 三、实施前必须完成的事项

1. 在正式上线前，机构确认适用法域、legal hold 负责人和数据删除审批人。
2. 实施服务端定时留存 worker：扫描到期 `speech_transcripts`，删除 Storage 对象、清空文本并记录审计事件；不得在数据库触发器中直接删除证据。
3. 已增加最简管理员登录页与账号开通脚本；仍需按 [`ADMINISTRATOR_ACCOUNT_SETUP.md`](ADMINISTRATOR_ACCOUNT_SETUP.md) 创建首个账号，并在隔离环境验证管理员跨机构拒绝。
4. 配置生产错误监控、备份恢复演练和删除 worker 失败告警。
